# kb_core：存储与服务端设计原理

- 日期：2026-11-05 03:45
- 状态：**当前实现说明**。操作手册见
  [`kb_svc/crates/kb_core/README.md`](../kb_svc/crates/kb_core/README.md)。

---

## 0. 边界

`kb_core` 负责：

1. 打开存储（当前是本地 MessagePack 文件，将来换 Turso）；
2. 把工作区 / 会话的按域 RPC 实现接到本机 UDS 上；
3. 常驻服务客户端（一次一个连接）。

它**不负责**：客户端配置、启动器、TCP 网关、LLM provider 本身。

---

## 1. 存储边界：`Store`

全部存储语义都在 `src/store_/`，对外只有 `Store` 一个类型。这是为了让
“换成数据库”有明确边界：`ipc_` 只依赖 `Store` 的方法，换实现时不动 RPC 代码。

```text
<storage_dir>/
├── workspaces/
│   └── <workspace_id>.mp
└── sessions/
    └── <workspace_id>/
        └── <session_id>.mp
```

文件内容是 `abs_kb_svc::v1::desktop` 协议类型的 **MessagePack**（`mp_denco`）表示：
**存储格式与线上格式同源**，不维护第二套结构，不会出现“能存进去、却发不出去”的字段。

---

## 2. 四条硬性约定

1. **标识必须能安全地当文件名**：只允许 ASCII 字母、数字、`-`、`_`，不超过
   128 字节；含 `../` 的标识在碰盘前就被拒绝。协议把标识当作不透明字符串，
   因此不能假定它一定由 `generate()` 产生。
2. **写入先落临时文件再 `rename`**：读到的是旧的或新的，不会是半个文件；
   强杀最坏留下 `*.mp.tmp`，不会被当成对象。
3. **会话属于工作区**：`create_session` / `list_sessions` 先确认工作区存在；
   删除工作区级联删除会话目录；工作区不存在时 `list_sessions` 返回错误而不是
   空列表（避免把“标识写错”误判成“没有会话”）。
4. **空会话不落盘**：会话要么有消息，要么有非默认名字（默认「新会话」）；
   两者都不满足时 `create_session` / `save_session` 返回
   `StoreError::EmptySession`。这样“新建会话”必须等第一次提问或先起名字，
   磁盘上不会堆积空会话。

这四条都有测试守着。

## 3. 可取消：每个操作都是宏展开的 future

`Store` 上**没有裸 `async fn`**。每个操作由
`gen_mcf2::gen_may_cancel_future` 展开成：

```text
store.list_workspaces().await?                      // 不可取消
store.list_workspaces().may_cancel_with(t).await?   // 可取消
```

取消的落点是 `race_cancel_`：**整个操作体**与取消信号赛跑；令牌先触发就返回
`StoreError::Cancelled`，尚未完成的等待随 future 一起被丢弃。

- 对 `compio::fs`，丢弃是真的取消 I/O；
- 对 `spawn_blocking` 里的阻塞任务，丢弃只是**不再等它**——换来调用方不被挂住。

私有辅助（`create_dir_all_` / `read_mp_` / `write_mp_` …）**不各自再包一层宏**：
它们只在已被令牌包住的操作体里调用，等待会随外层 future 一起被丢弃。
它们没有假定“调用者不会取消”，只是把取消交给唯一的外层统一处理。

`ipc_` 把请求带的取消令牌**继续传给** `Store`，而不是丢掉自己造一个；因此
“客户端撤销一次调用”能一路传到最后一次文件等待。

## 4. 服务端分层

```text
Listener / Connection（kb_svc_mptp_ipc）
  └─ KbServiceSet { handshake, workspace, session, generation }
       └─ kb_core::ipc_ 的四个薄包装
            └─ Store
```

- `ipc_` 只做三件事：校验/转发取消令牌、调用 `Store`、把 `StoreError` 翻成
  `ErrorCode`；
- 传输/协议错误与业务错误分层：服务端这一侧不产生传输错误，
  所有失败都是业务错误；
- 业务错误到线上是 460–466 状态码，客户端还原 `ErrorReply`（见传输文档）。

### 4.1 错误映射

| `StoreError` | `ErrorCode` |
| :--- | :--- |
| `NotFound` | `NotFound` |
| `InvalidId` / `EmptySession` / `EmptyName` | `BadRequest` |
| 其它（I/O、解码、阻塞任务） | `Internal` |

`Cancelled` 在服务端正常路径不会出现（派发层用不可取消令牌调用），但实现仍
保留检查——不假定调用者不会取消。

## 5. 生成域：临时模拟 LLM

`TrGeneration::ask` 目前没有真正的 LLM 插件可接，实现成：

```text
校验取消令牌
  → 读一次会话（拿现有 turns）
       ├─ 已经有本轮回答 → 原样返回
       ├─ 已经有本轮用户回合 → 只追加回答
       └─ 都没有 → 追加 user + assistant
  → 返回提问之后的完整会话
```

- 回答是问题按**字符**逆序（`chars().rev()`），中文不会碎成半个；
- 助手回合挂一条非错误的 `Notice`，提示“临时模拟”；
- 回答的 `turn_id` 由用户回合标识确定性推导（`t-1` → `t-1-a`），
  因此同一次提问重发是幂等的；
- 标题由 `normalize_title_` 推导：显式标题优先，否则取首条用户消息第一行前
  24 个字符，一条都没有则用「新会话」。

等真正的 LLM / 流式事件落地时，`ask` 的返回类型会换成流形状，`Event` / `Cancel`
才会真正被使用。

---

## 6. 运行时与并发

- `main` 用 `#[compio::main]`；文件读写走 `compio::fs`；
- 目录遍历、递归删除这类没有异步版本的操作交给 `spawn_blocking`；
- `Listener::accept` 是异步的；**一次只服务一个客户端**，上一个断开才回到 accept；
- 没有安装信号处理器，`Ctrl-C` 走操作系统默认处置。

并发服务多客户端、优雅退出、鉴权都是后续工作。
